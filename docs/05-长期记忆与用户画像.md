# 05 · 长期记忆与用户画像设计

> 对应母项目"记忆管理层"与"用户画像构建层"。代码落点：`geo_guard/memory.py`。
> 与多轮交互 PPT 架构页严格对齐：短期环形缓冲、长期向量库、时间衰减 w(t)=e^(-λt)、
> 动态状态向量（风险规避/价格敏感/品牌导向）、偏好冲突检测。

## 1. 三层记忆结构

```text
┌─ 工作记忆（会话内）──────────────────────────────┐
│  环形缓冲区, 最近 K=20 轮交互 + 当前任务链状态        │
│  直接进 LLM 上下文 / 规则引擎                       │
└──────────────────────────────────────────────┘
┌─ 情景记忆（跨会话事件）──────────────────────────┐
│  向量存储: "用户曾在X日甄别过Y商品, 结论=高风险"       │
│  检索: 语义召回 top-k × 时间衰减加权                 │
└──────────────────────────────────────────────┘
┌─ 语义记忆（结构化画像）──────────────────────────┐
│  动态状态向量 + 实体偏好表(品牌/品类/博主信任度)        │
│  存储: SQLite 结构化表, 全工作流共享                  │
└──────────────────────────────────────────────┘
```

## 2. 数据模型（SQLite 持久化）

```sql
-- 情景记忆
memories(id, user_id, kind,            -- screening/feedback/preference/event
         subject,                       -- 商品/品牌/博主实体名
         content,                       -- 记忆正文(进向量索引)
         risk_level,                    -- 甄别类记忆附带的结论档位
         importance REAL,               -- 0~1, 影响保留优先级
         created_at, last_accessed_at, access_count)

-- 语义记忆: 动态状态向量
profile_state(user_id, key, value REAL, confidence REAL, updated_at)
-- key ∈ {risk_aversion 风险规避, price_sensitivity 价格敏感,
--        brand_orientation 品牌导向, evidence_appetite 证据披露偏好}

-- 实体偏好/信任
entity_trust(user_id, entity, entity_type, trust REAL,  -- -1~1
             evidence_count, updated_at)
```

## 3. 时间衰减与召回

- 召回打分：`recall_score = cosine_sim × w(t) × (1 + log(1+access_count)×0.1)`，
  其中 `w(t) = e^(-λt)`，λ 按记忆类型分设：甄别结论 λ=1/90天（风险结论衰减慢——
  安全相关记忆宁可保守），一般偏好 λ=1/30天；
- **衰减≠删除**：低分记忆降权归档；importance ≥ 0.8 的记忆（高风险甄别结论、
  用户明确声明的偏好）不参与衰减清除；
- 记忆整合：会话结束时把短期缓冲中有长期价值的事件（用户明确偏好表达、甄别结论、
  反馈动作）提炼写入情景记忆——对应母项目"记忆整合与衰减机制"。

## 4. 画像更新与偏好冲突检测

### 4.1 更新来源（隐式+显式）

| 信号 | 更新动作 |
|---|---|
| 用户显式声明（"我预算300以内"） | 直接写 profile_state / entity_trust，confidence=1.0 |
| 对推荐的选择/拒绝 | price_sensitivity、brand_orientation 增量更新（EMA α=0.3） |
| 对警告的采纳/忽略 | risk_aversion 增量更新 |
| 对判定的异议 | 相关 entity_trust 下调 + 记忆标注 disputed |

### 4.2 冲突检测（母项目创新点："偏好与记忆冲突时自动修正画像并调整 RAG 检索权重"）

```text
触发条件: 当前请求语义 与 高置信画像项 矛盾
  例: 画像 price_sensitivity=0.9, 当前请求 "推荐旗舰款不差钱"
处理:
  1. 不静默改画像 —— 通过主动质询确认("您之前更关注性价比, 这次想看看高端款吗?")
  2. 用户确认 → 画像更新 + 冲突事件入情景记忆
  3. 用户否认 → 维持画像, 本次请求按会话级临时偏好处理
RAG 权重联动: 画像 risk_aversion 高 → 检索时 risk 类查询加权、
  推荐候选的 F4/F5 证据门槛提高(呈现更严格, 判定分数不变——D-08 红线)
```

### 4.3 画像的使用边界（D-08）

画像**只调制**：警告语气与强度、披露深度（evidence_appetite）、推荐排序、
质询策略；**永不调制**：risk_score 计算、阈值、证据链内容。
判定对所有人一致，这是审计公正性的底线，也是"第三方审计师"叙事的前提。

## 5. 隐私与用户主权（I-28）

- 全部记忆本地 SQLite，零云端上传；
- 命令/工具接口提供：`查看我的画像`、`删除某条记忆`、`清空全部数据`（一键、不可恢复需二次确认）；
- 导出：记忆库可导出为 JSON（用户带走自己的数据）。
