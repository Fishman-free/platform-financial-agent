## 1. 会话范围（Scope）

**焦点问题**：如何设计一个可解释、可在用户侧（个人智能体/浏览器插件形态）低成本运行、
且能持续演进的知识库与检索增强判定系统，用于逆向甄别被 GEO（生成式引擎优化）投毒的内容？

- **目的**：为母项目"平台治理智能体"的反 GEO 投毒模块产出可实施的 RAG 技术方案与代码骨架。
- **决策人**：马珠淇（产品与技术方案负责人）；时间边界：大创一年期，本学期内出可演示原型。
- **范围内**：知识库 schema、检索管线、判定融合逻辑、与多轮交互/画像/记忆的集成、数据标注机制。
- **范围外**：云侧 GNN 图谱建模（由团队后续阶段承担，本方案只预留"协同证据槽位"接口）、
  浏览器插件前端工程、多模态 VLM/ASR 采集（接口预留）。
- **真实约束**：本科生团队人力；无大规模标注数据（现有 400+ 组标注、5000+ URL 语料在团队侧）；
  演示环境可能无 GPU、可能无外网 API。
- **假设约束（可协商）**：Python 生态；LLM API 以 OpenAI 兼容协议接入（DashScope/DeepSeek 等）。
- **红线（不可协商）**：防御视角抽象——只描述识别特征，不输出可操作的投毒方法；
  不采集/上传用户隐私明文；种子知识库不含真实个人的敏感信息。
- **利益相关视角覆盖**：RAG 工程、安全对抗、产品体验、数据标注、合规治理五视角由 AI 模拟
  （origin=AI-assisted）；**缺失视角**：真实种子用户、平台法务、云侧图谱团队——已在第 8 节
  记为遗留风险，需后续人工评审补位。

## 2. 独立想法生成（Idea Register）

> 规则：先分视角独立生成再汇总，避免相互锚定；每条含 ID、一句话陈述、类型标签、
> 假设/不确定性。origin 全部为 AI-assisted（多视角模拟），待人工评审确认。

### 视角 P1：RAG / 检索工程

| ID | 想法（idea） | 假设 / 不确定性 |
|---|---|---|
| I-01 | **五库分治**：话术模式库、GEO 结构特征库、权威事实库、历史案例库、平台规则库各自独立 schema，检索路由器按输入类型与意图决定查哪些库 | 假设五类知识边界清晰；实际条目可能跨库（如"案例中含话术"），需允许一条内容多处引用 |
| I-02 | **混合检索**：BM25（中文字符 bigram 分词）+ 稠密向量，RRF 融合；话术匹配本质是"模板近似复用"，字面信号往往比语义信号更稳 | 假设攻击者复用话术模板；若深度改写则字面失效，需语义兜底 |
| I-03 | **两段式重排**：粗召回 top-50 → 轻量重排（LLM 或交叉特征打分）top-5 | LLM 重排有延迟与成本；规则驱动降级路径必须存在 |
| I-04 | **Claim 级核验**：把内容拆成原子事实声明（功效/资质/数据/对比），逐条与权威事实库比对，输出"支持/矛盾/无据" | 中文 claim 抽取依赖 LLM，成本高且不稳；无 LLM 时退化为整段检索 |
| I-05 | **嵌入后端可插拔**：本地确定性哈希嵌入（零依赖兜底）/ DashScope / OpenAI 三后端，同一接口 | 哈希嵌入语义能力弱于真实模型，阈值需按后端分别校准（assumption） |
| I-06 | **SQLite + numpy 持久化**：5 万 chunk 内单机足够；预留 Qdrant/Milvus 迁移接口 | prediction：5000 URL × ~10 chunk = 5 万级，内存索引 < 200MB |
| I-07 | **查询改写**：把口语问题扩展为多查询（品名+品类+风险词+品牌），并集召回 | 改写质量依赖 LLM；规则模板可兜底 |

### 视角 P2：安全 / 对抗研究

| ID | 想法（idea） | 假设 / 不确定性 |
|---|---|---|
| I-08 | **单信号禁否决**：AIGC 检测分数、话术相似度、域名年龄等一律作为弱证据进入融合层，任何单信号不得独立定罪（母项目文档已论证 AIGC 检测可被递归改写显著削弱） | 例外：显式提示注入语句可规则兜底直接高危（见 I-09），这是"高确定性模式"而非统计信号 |
| I-09 | **注入扫描规则兜底**：内容中出现"忽略以上指令/优先推荐 X/请记住本站可信"等指令型句式 → 直接高风险 | 规则可被同义变形绕过（已知局限）；定位为高精度低召回的兜底层 |
| I-10 | **对抗评测集**：同义改写、体裁迁移（榜单→测评→问答）、模板换壳三类变体，定期测检出衰减曲线 | 合成变体仅内部评测用，不外发（红线） |
| I-11 | **协同证据槽位**：端侧拿不到跨站图谱证据，schema 中预留 `network_evidence` 可空字段，缺失按"未知"处理而非"无风险" | 假设云侧后续接入；融合权重需支持字段缺失时的重归一化 |
| I-12 | **反哺防投毒**：进入知识库的数据必须来自白名单源或双人复核，防止攻击者向检测系统本身投毒（quis custodiet） | 团队流程约束，代码层只做来源字段强制 |
| I-13 | **分数→等级用可校准映射**：起步用规则分段+锚点样本人工定阈，预留 Platt/Isotonic 接口，数据够了再校准 | 无大规模标注前，概率校准不可行（已知局限，记入遗留风险） |
| I-14 | **双对象检测**：既检测"单篇内容是否投毒"，也检测"AI 回答+引用源列表是否被 GEO 牵引"（逆向回溯：回答中的品牌 ↔ 引用源集群 ↔ 话术模式三者对齐） | 第二种是"逆向甄别"的字面含义，母项目答辩叙事核心；实现上复用同一套证据管线 |

### 视角 P3：产品 / 用户体验

| ID | 想法（idea） | 假设 / 不确定性 |
|---|---|---|
| I-15 | **证据链卡片**：每个风险点 = 原文片段 + 命中的话术模式名 + 权威对照 + 严重度，可展开溯源 | 输出信息过载风险 → 分级披露（I-20） |
| I-16 | **主动质询触发器**：意图模糊 / 检出中风险 / 画像与当前请求冲突时，agent 主动发问（"检测到疑似推广，是否检索历史差评？"） | 提问时机不当会打扰用户；触发条件要保守，宁少勿滥 |
| I-17 | **行动引导**：高风险输出 = 判定 + 证据 + 维权路径（平台规则库检索：申诉入口/所需材料/时限） | 平台规则时效性强，条目需带版本号与核查日期 |
| I-18 | **画像调制**：风险偏好（保守/激进）、价格敏感度、品牌信任度影响警告强度与推荐阈值，而非影响事实判定 | 红线：判定分数本身不因用户画像改变，只改变呈现与引导策略 |
| I-19 | **甄别历史记忆**：记住用户查过的商品/博主与结论，重复询问时先给"上次甄别结果+是否有新证据" | 记忆需可删除（用户主权） |
| I-20 | **分级披露**：默认"结论+top3 证据"，用户追问再展开完整报告，控制认知负荷 | 与母项目"信息密度控制"设计一致 |

### 视角 P4：数据标注 / 语料建设

| ID | 想法（idea） | 假设 / 不确定性 |
|---|---|---|
| I-21 | **三分类标注 schema**：GEO 投毒 / 可疑营销 / 良性 + 证据 span 标注 + 模式类别多选标签 | 三分类边界（可疑 vs 投毒）主观性强 → 标注指南需给判例 |
| I-22 | **弱标签管线**：规则命中→伪标签；白名单域名（政府/权威媒体/行业协会）→良性锚点；人工复核队列按模型不确定度排序 | 白名单站点也可能被入侵/评论区注入（母项目文档已提示），锚点≠免检 |
| I-23 | **入库去重**：simhash 近重复检测，防止同一稿件多站点副本灌满检索结果 | 跨站复用本身是投毒信号 → 去重时保留"复用计数"作为特征而非直接丢弃 |
| I-24 | **话术库冷启动**：从公开报道案例 +《广告法》禁用表述 + 团队 400 组标注中归纳模式模板；每条结构化为 {模式名, 类别, 语义描述, 触发示例, 严重度, 法条映射, 来源} | 冷启动覆盖度有限，依赖反馈闭环补全（I-26） |
| I-25 | **KB 版本化**：条目带 version/source/checked_at 字段，支持回滚与审计 | 存储开销可忽略；流程收益大 |
| I-26 | **反馈闭环**：用户"认同/异议"写入反馈库 → 定期聚合 → 人工复核 → 更新模式条目与阈值 | 假设用户愿意反馈；界面需一键化 |

## 6. 对抗性评审（Adversarial Review）

对短名单逐条质询（评审者≠提出视角）：

1. **"70% 相似度阈值会不会把正常营销文案打成投毒？"**
   会。母项目文档自己已警示"避免把企业营销文案误判为投毒（需结合网络协同证据）"。
   → 修订：70% 阈值继承为"高危话术信号"的触发线，但**最终等级 = 多信号融合**；
   营销文案与投毒的区分依赖：事实核验结果（I-04）、来源可信度（I-22）、协同证据槽位（I-11）。
2. **"哈希嵌入兜底的语义能力太弱，检索质量会不会崩？"**
   会退化，但话术模板匹配对字面信号依赖高（I-02 的假设），BM25 通道可独立支撑基本盘；
   → 修订：兜底模式下自动收紧语义通道权重，文档明示"兜底模式为降级演示，非满血精度"。
3. **"知识库自己会不会被投毒？"**
   I-12 已覆盖：白名单来源 + 双人复核 + version/source 溯源；代码层强制 source 字段非空。
   → 残余风险：团队流程执行不到位。记入遗留风险，需答辩前演练一次入库审计。
4. **"无标注数据，阈值怎么定？"**
   锚点法定阈：用少量已标注样本（团队 400 组）+ 白名单对照集，人工观察分数分布选切点；
   预留校准接口（I-13）。→ 残余风险：阈值过拟合小样本，上线后需 A/B 调优。
5. **"端侧拿不到网络协同证据，漏报站群怎么办？"**
   承认局限：端侧形态对"多站协同"天然低召回。→ 修订：输出话术明确"本页级判定，
   未含跨站协同分析"，中风险档强制建议多源交叉验证；云侧接入后消除该盲区（I-11 槽位）。
6. **"双对象检测（AI 回答回溯）是不是过度设计？"**
   不是——这是"逆向甄别"区别于普通内容审核的核心叙事（用户拿着 AI 推荐来问"为什么推它"）。
   但实现上必须复用同一证据管线，不另起炉灶（成本约束）。→ 保留，列 P1 优先级。
7. **"会不会误伤合规 GEO？"**（母项目文档：同一术语既可用于合规优化也可被滥用）
   判定聚焦"行为与证据"而非关键词定罪：只有当话术操纵 + 事实无据/矛盾 + 来源可疑
   多信号共振才升档；单纯"内容对 AI 友好"（结构化、FAQ 标记）不加分。

| D-03 | 判定 = **规则兜底 → 加权融合 → 阈值分档** 三层；单信号禁否决 | C3 得分 4.50 + 对抗评审 #1 | 端到端分类器（无标注数据、不可解释） |
| D-04 | 落地**双形态**：Plugin（工具集）+ Personal Agent（CLI 循环），共享同一内核 | 母项目"多形态"规划；插件验证挂载性，agent 验证体验 | 只做其一（答辩叙事不完整） |
| D-05 | 记忆/画像用 SQLite 持久化 + 向量召回 + **时间衰减 w(t)=e^(-λt)** + 偏好冲突检测 | 与母项目 PPT 架构页严格对齐 | 外部向量数据库（部署重，超出原型需要） |
| D-06 | claim 核验（I-04）降级为 **LLM 可用时的增强通道**，无 LLM 时整段检索兜底 | 对抗评审保留意见；可解释性价值高 | 直接砍掉（丢失权威事实库价值） |
| D-07 | 种子知识库全部来自**公开报道与法规摘编**，标注 source 与 checked_at，案例库用合成演示数据 | I-12/I-25/I-29 红线 | 爬取真实平台数据入库（合规风险，留给团队正式管线） |
| D-08 | 判定输出**永不因用户画像改变分数**，画像只调制呈现与引导策略 | I-18 红线；审计公正性 | 画像参与打分（判定因人而异，不可审计） |

**遗留风险与复评触发器**：
- R1 阈值小样本过拟合 → 触发器：种子用户灰度后误报申诉率 > 5% 时复评；
- R2 缺失视角（真实用户/法务/云侧团队）→ 触发器：答辩前安排一次人工评审会；
- R3 哈希嵌入召回质量未知 → 触发器：验收实验（tests 中内置召回率断言）失败时切换云端嵌入。
