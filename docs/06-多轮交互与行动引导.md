# 06 · 多轮交互与行动引导设计

> 对应母项目"工作流三：多轮交互和行动引导"——系统的智能交互与任务协调中枢。
> 代码落点：`geo_guard/dialogue.py`。三层协同：交互控制层、任务规划层、记忆管理层
> （记忆层见 docs/05）。

## 1. 对话状态机（交互控制层）

```text
            ┌──────────┐
   用户输入 →│  IDLE     │
            └────┬─────┘
                 ▼
         ┌───────────────┐  意图不明/信息不足   ┌──────────────┐
         │ INTENT_PARSE   │──────────────────►│ CLARIFYING    │◄─┐
         └────┬──────────┘                    │ (主动质询)      │──┘ 用户补充
              │ 意图明确                        └──────┬───────┘
              ▼                                        │ 放弃/三次未明
     ┌────────────────┐                                ▼
     │ TASK_PLANNING   │                          降级为一般建议
     │ (生成行动链DAG)  │
     └────┬───────────┘
          ▼
   ┌──────────────┐  检出≥中风险   ┌───────────────────┐
   │ EXECUTING     │──────────────►│ RISK_PRESENTING    │
   │ (调度子任务)    │               │ (证据链卡片+质询入口) │
   └────┬─────────┘               └────────┬──────────┘
        │ 完成                               ▼
        ▼                          ┌───────────────────┐
   ┌──────────────┐               │ ACTION_GUIDING     │
   │ RESPONDING    │◄──────────────│ (维权路径/下一步建议) │
   └────┬─────────┘               └───────────────────┘
        ▼
   等待下一轮 / 会话结束(触发记忆整合)
```

状态对象：`DialogueState {phase, pending_question, task_dag, turn_history(环形缓冲), snapshot}`。
**中断恢复**：每次状态迁移持久化快照（SQLite），进程重启后从最近快照续行——对应
PPT 架构页"快照保存·断点续行"。

## 2. 主动质询触发器（何时问、问什么）

触发器 = 规则触发 ∪ LLM 决策（母项目双轨设计），**宁少勿滥**（对抗评审：打扰成本）：

| 触发条件 | 质询模板（示例） |
|---|---|
| 意图模糊（无品类/无对象） | "您想甄别的是哪类内容？可以把链接或文案发给我" |
| 检出 MEDIUM 风险 | "检测到该内容命中{n}类可疑话术，是否需要我检索历史差评与权威对照？" |
| 检出 HIGH 风险 | "该内容风险较高。需要我生成维权路径和证据清单吗？" |
| 画像冲突（docs/05 §4.2） | "您之前更关注性价比，这次想看看高端款吗？" |
| 推荐多候选难分 | "这两个候选风险等级相同，您更在意价格还是品牌信用？" |
| 任务链分叉点 | "评论区发现集中负评，深挖评论(慢) 还是 直接查博主信用(快)？" |

LLM 决策通道（有 API 时）：把当前状态+画像+候选问题交给 LLM 判断"现在是否提问最佳时机、
哪个问题最能推进任务"；规则通道永远兜底，保证无 API 时行为可预期。

## 3. 任务规划层：行动链 DAG

### 3.1 原子动作集（对齐 PPT：ask / show / call / confirm）

| 动作 | 语义 | 执行器 |
|---|---|---|
| `ask` | 向用户提问并等待 | 状态机 → CLARIFYING |
| `call:screen` | 内容甄别 | GeoGuard.screen_content |
| `call:trace` | AI 回答回溯 | GeoGuard.trace_ai_answer |
| `call:comments` | 评论有效性分析 | features.comment_channel |
| `call:credit` | 博主信用评估 | KB4 influencer_record 检索 |
| `call:verify` | 事实核验 | claims.verify |
| `call:memory` | 记忆召回/写入 | MemoryStore |
| `show` | 展示证据卡片/报告 | explain 渲染 |
| `confirm` | 请求用户确认（高危操作/画像修正） | 状态机 |

### 3.2 典型 DAG（母项目口红示例的甄别版）

```text
用户: "这个博主推荐的口红能买吗?"(附文案)
  T1 call:screen(文案)            ──► risk=MEDIUM, 命中 exaggeration
  T2 ask("要查历史差评和成分核验吗?") ──► 用户: 要
  T3 call:comments(商品)  ∥ T4 call:verify(成分声明)     [可并行]
  T5 call:credit(博主)             ──► 依赖 T3/T4 结果聚合
  T6 show(综合报告)
  T7 IF risk≥MEDIUM: call:rules(申诉路径) → show(行动建议)
```

### 3.3 执行引擎语义

- 依赖驱动调度：入度为 0 的节点先执行，支持并行标记（`∥`）；
- **动态重规划**：任一节点输出 HIGH → 中断后续推荐类节点，插入 `show(警告)+ask(维权引导)`
  （母项目原文："若鉴别输出高风险，行动链立即中断推荐流程，转执行生成风险预警"）；
- 失败降级：节点异常 → 标记 skipped，DAG 继续（证据缺失在报告中声明，不静默吞掉）；
- 每个节点执行结果写入工作记忆，跨会话可恢复。

## 4. 信息密度控制与可解释生成（交互控制层）

- **分级披露**（I-20）：默认输出 = 结论 + top3 证据；`show` 动作支持
  `detail=summary|standard|full` 三档，由画像 evidence_appetite 决定默认档位，用户可随时升级；
- **可解释生成**：所有结论句式模板化嵌入证据引用（"[证据1] 命中'无依据权威背书'话术，
  相似度 0.83"），LLM 润色时证据编号与链接不可删改（prompt 约束 + 输出校验）；
- **认知负荷**：单轮输出证据卡片 ≤ 3 张，超出折叠为"还有 n 条证据，回复'展开'查看"。

## 5. 与其他模块的接口契约

| 对方 | 契约 |
|---|---|
| GEO 甄别内核（docs/02） | RiskReport.proactive_prompts[] → 触发器候选问题；MEDIUM 强制携带 ≥1 个质询建议 |
| 记忆画像（docs/05） | 读：召回历史甄别与画像调制呈现；写：会话结束触发记忆整合；画像修正必须走 `confirm` |
| 插件形态（docs/07） | DAG 节点一一映射为插件工具；宿主 Agent 可只调用单节点（无状态模式） |
