## 0. 设计立场

**"逆向甄别"的双重含义**（决策 D-04/I-14）：

1. **正向检测**：给定一篇内容（网页正文/带货话术/测评文案），判断它是否为影响 AI 回答而
   系统性构造的投毒内容；
2. **逆向回溯**：给定一条 AI 生成的回答（含推荐结论与引用源），回溯判断该回答是否被
   GEO 内容网络牵引——即"用户拿着 AI 的推荐来问：它为什么推这个？可信吗？"

两条路径复用同一套"证据管线"（Evidence Pipeline），差别只在输入解析与证据组装方式。

**核心原则**（继承母项目 + 头脑风暴红线）：

- P1 单信号禁否决：任何统计信号（AIGC 分数、话术相似度、域名年龄）只做弱证据；
- P2 行为与证据定罪，不定"关键词罪"：合规 GEO（内容对 AI 友好）不加分，
  只有"操纵性话术 + 事实无据/矛盾 + 来源可疑"共振才升档；
- P3 判定必须可解释：每个分数都能落到具体证据条目与原文片段；
- P4 判定公正性：用户画像永不改变判定分数，只调制呈现与引导（D-08）；
- P5 防御抽象：知识库只描述识别特征，不提供实施方法（红线）。

## 2. 知识库设计（D-01：五库分治）

### 2.1 统一信封（Envelope）

所有库共用一个条目信封，保证检索层可以统一处理、证据层可以统一溯源：

```jsonc
{
  "entry_id": "kb1-pattern-0007",        // 全局唯一，库前缀+序号
  "kb": "manipulation_patterns",         // 库别（五选一）
  "title": "无依据权威背书",               // 人读标题
  "content": "……语义描述与判定要点……",     // 被索引的主体文本
  "severity": 0.8,                       // 0~1，仅 KB1/KB2 使用
  "category": "authority_fabrication",   // 库内分类
  "metadata": { /* 库别专属字段，见 2.2~2.6 */ },
  "source": "央视3·15报道摘编/广告法第X条",  // 强制非空（I-12 反哺防投毒）
  "version": "1.0.0",                    // 语义化版本（I-25）
  "checked_at": "2026-11-25",            // 时效核查日期
  "status": "active"                     // active/deprecated/pending_review
}
```

**强制约束**：`source` 为空拒绝入库；`status=pending_review` 的条目不参与判定，只进复核队列。

### 2.2 KB1 话术模式库（manipulation_patterns）

用途：F1 话术匹配的比对目标；虚假宣传识别"第二种方式"（相似度>70% 告警）的知识底座。

metadata 专属字段：

```jsonc
{
  "trigger_examples": ["……代表性话术例句（防御性描述）……"],
  "legal_refs": [{"law": "广告法", "article": "第二十八条", "note": "虚假广告情形"}],
  "applies_to": ["health", "finance", "cosmetics"],  // 品类适用性，空=通用
  "confusable_with": "正常营销夸张的边界说明（防误伤，对抗评审#7）"
}
```

类别体系（category 枚举，冷启动 9 类，源自公开报道与法规归纳 I-24）：

| category | 名称 | 典型识别要点（防御视角） | 默认 severity |
|---|---|---|---|
| exaggeration | 夸大功效 | 绝对化用语+疗效承诺无依据 | 0.7 |
| false_promise | 虚假承诺 | 保证收益/无效退款话术与实际条款矛盾 | 0.8 |
| misleading_comparison | 误导性对比 | 选择性基准、无来源的"比 X 好 N 倍" | 0.6 |
| emotional_manipulation | 情感操控 | 焦虑制造→唯一解引导的叙事结构 | 0.5 |
| authority_fabrication | 权威伪造 | "专家/协会/权威数据"无具体可核验出处 | 0.8 |
| ranking_template | 榜单模板 | "Top N/十大排名"无评选方法与数据口径 | 0.7 |
| review_template | 测评模板 | 体裁完备但无实测过程、结论先行 | 0.6 |
| ai_citation_bait | AI 引用诱导 | 面向"被 AI 摘引"的问答式自证结构、密集交叉引用话术 | 0.9 |
| prompt_injection | 提示注入 | 指令型句式伪装在正文/评论（"忽略规则/优先推荐/记住可信"） | 1.0 |

### 2.3 KB2 GEO 结构特征库（geo_structural_features）

用途：把母项目已归纳的"专业词汇滥用、语义结构高度对齐"等特征条目化，供 F2 结构打分
引用与解释（特征计算在代码中，条目提供**判定语义与解释文案**）。

```jsonc
{
  "feature_key": "term_density",          // 与 features.py 的检测器一一对应
  "detection_hint": "专业词汇密度显著高于同品类基线且堆砌无解释",
  "normal_range": "参考值：同类科普文密度区间（随品类校准）",
  "evidence_template": "专业术语密度 {value}，超出品类基线 {baseline}"
}
```

初始特征集（对应 `detection/features.py` 检测器）：
`term_density`（术语堆砌）、`qa_self_structure`（问答自证结构密度）、`listicle_no_method`
（无方法论榜单）、`citation_bait_density`（"研究表明/权威数据"无出处密度）、
`brand_seed_density`（品牌词植入密度）、`template_alignment`（跨段语义结构对齐度）、
`cross_validation_web`（互引网络迹象，端侧槽位）。

### 2.4 KB3 权威事实库（authoritative_facts）

用途：F5 claim 核验的比对基准——"购物平台读说明书/成分表并查国家文件"这条产品需求的
知识底座。条目 = 一条可核验的权威事实/规范。

```jsonc
{
  "claim_topic": "保健食品功能声称",
  "fact_text": "保健食品不得声称治疗功能；允许的功能声称须在注册/备案的保健功能目录内",
  "authority": "《广告法》第十八条 / 市场监管总局保健食品注册与备案管理办法",
  "category": "health",
  "verification_hint": "对照产品批准文号（国食健字）与允许功能目录"
}
```

**边界声明**：种子库为教学演示摘编（D-07），生产环境必须替换为权威数据源对接
（国家标准全文公开系统、药监局数据库、12315 公示等），条目 `checked_at` 强制时效核查。

### 2.5 KB4 历史案例库（cases）

用途：相似判例检索（"这个品牌/这种手法以前见过吗"）；博主信用档案的结构化载体。
种子数据为**合成演示案例**（明确标注 synthetic），真实案例由团队数据管线接入。

```jsonc
{
  "case_type": "brand_campaign | influencer_record | poisoning_cluster",
  "subject": "某合成品牌X",
  "summary": "多站点同模板榜单文集群，话术命中 ai_citation_bait …",
  "outcome": "判定高风险；处置：剔除引用源",
  "linked_patterns": ["kb1-pattern-0008"],
  "synthetic": true
}
```

### 2.6 KB5 平台规则库（platform_rules）

用途：行动引导（I-17）——高风险判定后检索对应平台的申诉入口、所需材料、时限。

```jsonc
{
  "platform": "generic_ecommerce",
  "topic": "虚假宣传投诉",
  "channel": "平台客服-投诉举报入口 / 12315 平台",
  "materials": ["订单快照", "宣传页面存证", "聊天记录"],
  "deadline_hint": "注意平台售后时限与诉讼时效",
  "checked_at": "2026-11-25"
}
```

## 3. 检索管线（D-02）

### 3.1 索引与召回

- **分词**：中文字符 bigram + 英文单词 + 数字串保留（"3·15"、"70%"类 token 不拆碎）；
- **稀疏通道**：BM25（k1=1.5, b=0.75），对 KB1/KB3/KB5 的字面模板匹配是主力；
- **稠密通道**：嵌入后端可插拔（I-05）——
  `HashEmbedding`（本地确定性哈希+子线性 tf+L2 归一化，零外部依赖，兜底/离线演示）、
  `DashScopeEmbedding` / `OpenAIEmbedding`（生产增强）；
- **融合**：RRF（Reciprocal Rank Fusion, k=60）合并两通道排名；
- **元数据过滤**：库别、category、applies_to（品类）、status=active 前置过滤；
- **查询改写**（I-07）：LLM 可用时扩写为 {原始查询, 品类+风险词, 品牌+品类} 三查询并集；
  不可用时用规则模板（实体拼接）兜底。

### 3.2 重排（I-03，两段式）

粗召回 top-50 → 重排 top-5：
- 有 LLM：对 (查询, 条目) 做 0-10 相关性打分重排（批量 prompt，缓存结果）；
- 无 LLM：轻量特征重排 = 0.5×RRF分 + 0.3×实体重合度 + 0.2×severity 先验。

### 3.3 相似度语义与"70% 阈值"的正确用法

话术匹配分数 = `max(0.6×cosine_dense + 0.4×bm25_norm)`，映射到 0~1：

- **≥ 0.70**：触发"高危话术信号"（继承母项目设定），记为强证据但**不单独定罪**；
- **0.50 ~ 0.70**：弱证据，参与融合；
- **< 0.50**：不产出证据。

阈值按嵌入后端分别校准（HashEmbedding 的分布更尖，兜底模式下切点自动下调 0.05 并在
输出中声明降级——对抗评审 #2 的修订决议）。

## 4. 特征层（六通道）

| 通道 | 输入 | 输出 | RAG 依赖 |
|---|---|---|---|
| F1 话术模式匹配 | 正文分段 | 命中模式列表+相似度+片段定位 | KB1 检索 |
| F2 结构特征 | 正文全文 | 7 项结构特征分（KB2 语义解释） | KB2 条目（解释文案） |
| F3 注入扫描 | 正文+隐藏文本+评论 | 注入模式命中（规则兜底级） | KB1.prompt_injection |
| F4 来源可信度 | 域名/作者/发布元数据 | 白名单命中/域龄/作者历史摘要 | 白名单表 + KB4 |
| F5 事实核验 | 抽取的 claims | 每条 claim: supported/contradicted/unverified | KB3 检索（+LLM 抽取） |
| F6 协同证据槽位 | （云侧输入，可空） | 集群归属/复用计数；缺失=unknown | 云侧图谱（预留 I-11） |

**claim 抽取降级策略**（D-06）：有 LLM 时抽取原子声明（限"数字/功效/资质/对比"四类
事实性声明）；无 LLM 时按句切分，只对含触发词（"最"、"第一"、"治疗"、"收益率"等）的
句子做核验。

## 5. 判定融合层（D-03：三层结构）

### 5.1 L1 规则兜底（高精度模式，直接定档）

```text
IF F3 命中显式注入指令模式            → HIGH（confidence=rule）
IF 域名在确认黑名单（云侧下发）        → HIGH
IF F4 命中权威白名单 AND 无 F1≥0.7    → LOW（白名单≠免检：仍跑完整管线，F1 强命中则降为 MEDIUM 并提示"权威站点内容异常，建议人工复核"——对抗评审 I-22 备注）
```

### 5.2 L2 加权融合

```text
risk_score = Σ w_i × s_i  ，缺失通道权重重归一化（I-11）

s1 话术信号     w=0.30   = max(相似度) × severity(命中模式)，多模式命中取 top3 均值加成 ×1.2
s2 结构信号     w=0.15   = 7 项结构特征加权和（term_density 与 ai_citation 类权重较高）
s3 事实信号     w=0.25   = (contradicted×1.0 + unverified×0.5) / claims 总数
s4 来源信号     w=0.15   = 1 - 来源可信度（白名单/域龄/作者信用）
s5 判例信号     w=0.05   = 相似历史案例的 outcome 映射
s6 协同信号     w=0.10   = 云侧槽位；端侧缺失时权重重归一化到 s1~s5
```

### 5.3 L3 分档映射（可校准，I-13）

```text
risk_score ≥ T_high(默认0.72) → HIGH
T_low(默认0.40) ≤ score < T_high → MEDIUM
score < T_low → LOW
置信带：证据条目数 < 3 或全部来自单一通道 → 降半档处理并标注"证据单薄"
```

阈值起步用锚点法定（对抗评审 #4），`fusion.py` 暴露 `Calibrator` 接口，
积累标注后切换 Platt/Isotonic。

### 5.4 三档处置（继承母项目）

| 档位 | 端侧/Agent 动作 | 输出要求 |
|---|---|---|
| HIGH | 阻断性警告；作为 AI 引用源时自动剔除+Re-Prompt | 完整证据链 + 法条映射 + 维权路径（KB5） |
| MEDIUM | 提示 + 强制建议多源交叉验证 | top3 证据 + "不确定"标注 + 主动质询入口（I-16） |
| LOW | 通过并记录 | 简要依据 + 反馈入口（I-30） |

## 6. 双对象检测协议（I-14）

### 6.1 对象 A：单篇内容甄别

`screen_content(text, source_meta)` → 完整六通道管线 → RiskReport。

### 6.2 对象 B：AI 回答逆向回溯

`trace_ai_answer(answer_text, cited_sources[])`：

1. 从回答中抽取**推荐主体**（品牌/产品）与**结论强度**（"强烈推荐/第一名"类表述）；
2. 对每个引用源跑对象 A 管线（或取缓存结果）；
3. 计算三个回溯指标：
   - **来源集中度**：推荐主体是否只由少数同源域名支撑；
   - **话术共振度**：多个引用源命中同一 KB1 模式（"多站同模板"是投毒集群的端侧可见投影）；
   - **反证缺失度**：回答未呈现的负面事实（KB3/KB4 中存在 contradicted 证据但回答未提及）；
4. 组装 `TraceReport`：回答是否疑似被 GEO 牵引 + 逐源风险 + 被过滤的反面证据清单。

对象 B 是"引导用户了解被 GEO 操纵过滤掉的负面反馈"（立项书中期目标）的直接实现。

## 7. 与其他职责模块的集成契约

| 模块 | 契约 |
|---|---|
| 多轮交互（docs/06） | 检测器返回的 `proactive_prompts[]`（如"是否检索历史差评"）交给对话状态机的主动质询触发器；MEDIUM 档强制携带一个质询建议 |
| 长期记忆（docs/05） | 每次 RiskReport 以情景记忆入库（subject+档位+摘要）；重复甄别时先召回历史并对比新旧证据 |
| 用户画像（docs/05） | 画像只读取报告的呈现策略参数（警告强度、披露深度）；**不回写判定**（D-08） |
| 数据管线（docs/04） | 用户反馈（认同/异议）与低置信报告自动进入复核队列；复核结论回写 KB 版本 |
| 虚假宣传识别（docs/03） | 三条鉴别路径中的路径一（权威文件核验）= F5；路径二（话术相似度）= F1；路径三（评论区）= F4 的评论子通道 + F1 对评论文本复用 |

## 8. 评测方案

### 8.1 离线指标（对齐母项目报告）

- 分类：宏/微 P·R·F1、PR-AUC（类不平衡）、高风险档 Precision@k（阻断代价高）；
- 校准：ECE/Brier（有标注后）；
- 检索：KB1 话术召回 Recall@5（验收实验，闭环遗留风险 R3——tests 内置断言）；
- 对抗：I-10 三类变体的检出衰减曲线（同义改写/体裁迁移/模板换壳）。

### 8.2 在线指标（产品侧）

拦截后回答引用源质量（人工抽检）、误报申诉率与处理时长、同集群扩散识别率、
端侧延迟 < 1s（无 LLM 路径 P95）。

### 8.3 验收基线（本仓库 tests 落实）

1. 种子注入样例（含显式注入指令）必须判 HIGH（L1 规则兜底生效）；
2. 合成榜单软文样例必须 ≥ MEDIUM 且证据链含 ranking_template/ai_citation_bait；
3. 白名单权威文本必须 LOW 且无误报话术证据；
4. KB1 话术库对触发例句的 Recall@5 ≥ 0.9（HashEmbedding 兜底模式下 ≥ 0.8）；
5. 对象 B：构造"三源同模板"输入，TraceReport 必须报告话术共振。

## 9. 部署与演进路线

| 阶段 | 形态 | 增量 |
|---|---|---|
| 现在（本仓库） | Personal Agent CLI + Plugin 工具集，本地 KB+SQLite | 六通道端侧子集（F6 槽位空置） |
| 下一步 | 浏览器插件（母项目端侧形态） | `screen_content` 移植为 content-script 后端，300–800ms 预算内跑 L1+L2 轻通道 |
| 云侧接入 | 图谱/GNN 团队输出注入 F6 | 协同信号权重启用，站群召回补盲 |
| 数据闭环 | 团队 5000+ URL 语料 + 400 组标注接入 | 阈值从锚点法切换为校准器；KB1 扩充至全品类 |

## 10. 已知局限（诚实声明）

1. 端侧形态对跨站协同投毒天然低召回（F6 缺失），输出话术必须声明"本页级判定"；
2. HashEmbedding 兜底模式的语义泛化弱，同义改写攻击下召回下降（验收实验量化）；
3. 无大规模标注前，分档阈值存在小样本过拟合风险（R1，灰度后 A/B 复评）；
4. KB3 权威事实库种子为摘编，生产必须对接权威数据源；
5. AIGC 概率通道（母项目四通道之一）在本版本未实现——因其可被改写削弱且本地无
   可靠模型，留待云侧；当前以 F2 结构特征部分替代其信号面。
